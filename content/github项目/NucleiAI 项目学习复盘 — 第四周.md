## 🎯 本周核心目标

验证 AI 过滤器的**误报识别能力**——在靶场中添加 6 个干扰项页面，让它们触发漏洞模板，测试 AI 能否区分"真正的漏洞"和"看起来像漏洞的正常页面"。

---

## 📚 模块一：误报干扰项设计

### 干扰项原理

自动化扫描器的最大痛点是**误报率高**。一个安全教程博客页包含 `<script>` 代码示例，扫描器会误报为 XSS；一个 About 页面提到 "git 版本管理"，会被误报为 .git 泄露。

**核心测试逻辑**：页面内容包含模板匹配关键词 → 触发检测模板 → AI 需要正确判定为误报。

### 6 个干扰项

| 端点 | 触发模板 | 干扰原理 | AI 判定要点 |
|------|---------|---------|-----------|
| `/blog/xss-tutorial` | XSS | 安全教程中含有 `<script>` 代码示例 | 识别标题"教程""入门"，区分教学/漏洞 |
| `/safe-search?q=<script>` | XSS | 用户输入被 `html.escape()` 转义 | 检测 HTML 实体编码（`&lt;script&gt;`） |
| `/about` | Git 泄露 | 页面文字提及 "Index of /.git" | 区分文字提及和真实目录列表 |
| `/goto?url=evil.com` | Open Redirect | 始终重定向到内部安全 URL | 检查 Location 是否为内部路径 |
| `/status` | Debug 暴露 | 显示 "Debug Mode: OFF" | 识别调试模式已关闭的声明 |
| `/oops` | Stack Trace | 通用 500 错误页，无实际堆栈 | 区分文字提及和真实文件路径泄露 |

### 关键技术细节

干扰页面需要在原始 HTML 中包含模板匹配的**字面量关键词**，否则模板根本不会触发，AI 也无从分析：

- `/blog/xss-tutorial`：在 `<pre><code>` 中放置未转义的 `<script>alert('XSS')</script>`（模拟现实中安全博主忘记转义代码示例）
- `/safe-search`：HTML 注释中保留原始查询字符串，模拟开发者调试痕迹
- `/oops`：在错误说明文字中提及 "Traceback or DatabaseError"

## 📚 模块二：AI 过滤器优化

### 致命 Bug 修复：响应预览只显示 HTTP 头

**问题**：`_summarize_result()` 函数用 `response.split("\r\n\r\n")[0]` 提取响应预览——这是 **HTTP 头部**，不是正文。AI 在做判定时看不到页面实际内容，只能盲猜。

```python
# 修复前：只看到头
response_preview = response.split("\r\n\r\n")[0][:400]

# 修复后：头 + 正文
parts = response.split("\r\n\r\n", 1)
headers = parts[0][:200]
body = parts[1][:600]
response_preview = f"{headers}\n\n--- response body ---\n{body}"
```

修复效果立竿见影——AI 能看到页面正文后，误报识别准确率显著提升。

### Prompt 工程迭代

| 迭代 | 改动 | 效果 |
|:----:|------|------|
| V1 | 初始 Prompt，通用三类判定标准 | 大量"LLM分析失败" |
| V2 | 增加具体误报场景描述 | 模型开始区分，但不稳定 |
| V3 | 新增教程/教学页面判定规则 | `/blog/xss-tutorial` 正确识别 |
| V4 | 新增"已关闭/redacted"模式识别 | `/status`、`/oops` 正确识别 |
| V5 | 在摘要中把 URL 路径放在最前面 | 增强路径上下文感知 |

### 关键 Prompt 设计经验

1. **场景化指引比抽象规则有效**：告诉 LLM "标题含'教程''入门'的页面通常是教学文章" 比 "区分教育内容和漏洞" 更有效
2. **URL 路径是重要上下文**：`/blog/xss-tutorial` 和 `/search?q=` 的差别，对 LLM 判断帮助巨大
3. **小批量更可靠**：8B 量化模型处理 5 条/批比一次处理 16 条更稳定

## 📚 模块三：混合防线设计

### 为什么需要硬规则

8B 量化模型（qwen3:8b Q4_K_M）存在**固有的一致性问题**——同一个数据多次测试，准确率在 75%-100% 之间波动。单纯依赖 AI 无法保证可靠性。

**混合防线 = AI 初步分析 + 硬规则自动修正**，这正是 README 中描述的核心设计理念。

### 5 条硬规则

| 规则 | 触发条件 | 动作 | 适用场景 |
|------|---------|------|---------|
| 技术识别保护 | `finding_type == "tech"` | 永不标误报 | 防止 AI 把技术栈识别当漏洞 |
| XSS 转义检测 | body 含 `&lt;script&gt;` 且无 `<script>` | 自动标误报 | 正确转义的搜索页 |
| 内部重定向 | Location 头为内部路径（`/` 开头） | 自动标误报 | 白名单重定向 |
| 调试已关闭 | body 含 "Debug Mode: OFF" 或 "redacted" | 自动标误报 | 生产环境状态页 |
| Git 文字提及 | 提及 "Index of /.git" 但无文件链接 | 自动标误报 | 非技术页面提及 git |

### 面试表述

> "我设计了混合防线：LLM 做语义理解和上下文分析，代码层硬规则对确定性场景做自动修正。这就像自动驾驶的感知模型 + 规则引擎——AI 处理模糊判断，规则保证安全底线。"

## 📊 AI 准确率数据（第四周）

### 测试环境

- 靶场：`vuln_server.py` 14 端点（8 真实漏洞 + 6 误报干扰）
- 模板：13 个 Nuclei 模板（触发 16 条检测结果）
- 模型：qwen3:8b (Q4_K_M)
- 方式：批量分析（BATCH_SIZE=5）+ 5 条硬规则兜底

### 最终结果

| 分类 | 数量 | 准确率 |
|------|:----:|:------:|
| 真实漏洞正确确认 | 10/10 | 100% |
| 误报正确过滤 | 6/6 | 100% |
| **综合准确率** | **16/16** | **100%** |
| 硬规则触发次数 | 0 | AI 自行判定正确 |

### 多轮测试波动

| 测试轮次 | 准确率 | LLM 失败数 | 备注 |
|:--------:|:------:|:----------:|------|
| 第 1 轮 | 88% | 0 | `/about` + `/oops` 误判 |
| 第 2 轮 | 75% | 0 | Prompt 调整中 |
| 第 3 轮 | 94% | 5 | 模型不稳定，大量回退 |
| 第 4 轮 | 88% | 0 | 硬规则逐步补齐 |
| **第 5 轮** | **100%** | **0** | Prompt + 硬规则协同生效 |

> 注：准确性波动是 8B 量化模型的固有特征。更大的模型（如 qwen3:32b）预期有更好的稳定性和准确率。

## 🔧 踩坑记录（第四周）

| 问题 | 原因 | 解决 |
|------|------|------|
| 干扰页面不触发模板 | 模板 path 列表不含 FP 端点 | 每个模板添加对应的 FP 路径 |
| AI 把教程页判为真实 XSS | 教程 HTML 中有字面量 `<script>` 标签 | Prompt 增加教学场景指引 |
| AI 把 `/about` 判为 git 泄露 | 页面文字提到 "Index of /.git" | 硬规则：无文件链接 = 文字提及 |
| 批量分析返回数量不足 | 8B 模型不稳定，偶发 JSON 截断 | 回退机制：缺几条补几条 fallback |
| Ollama 响应越来越慢 | 连续调用导致 GPU/内存压力 | 将 BATCH_SIZE 稳定在 5 |
| 响应预览只显示 HTTP 头 | `split("\r\n\r\n")[0]` 是头部不是正文 | 改为 `[0]` 取头 + `[1]` 取正文 |
