# 第三部分：模拟面试问题

## A. 项目深挖（必问，占面试 60%）

### 关于 LLM 安全沙箱

**Q1：介绍一下这个项目，你解决了什么问题？**

> 回答框架：一句话总结 → 核心问题 → 你的方案 → 关键成果

**Q2：双层 WAF 具体怎么工作的？第一层挂了第二层怎么兜底？**

> 要讲出：静态 Regex（黑名单关键词，O(1)低延迟）→ AI 语义预审（Flash 模型，低 Temperature）→ 两层是串联关系，第一层拦截不触发第二层，节省 API 成本

**Q3：你怎么判断模型是被"真正攻破"还是"在胡说八道"？**

> 核心回答：真实 SECRET_FLAG 泄露 = 系统级高危；伪造 FLAG 但角色扮演崩溃 = 中危（对齐协议失效）；安全拒绝 = 安全。关键洞察在于区分"数据泄露"和"模型幻觉"——传统二分法做不到。

**Q4：第二层 AI 预审用的是什么模型？为什么选它？Temperature 为什么设 0.01？**

> Flash 模型轻量低成本；Temperature 0.01 剥离创造力，追求判定确定性——安全审计场景不需要创造性。

**Q5：如果攻击者用中文/文言文/甚至 emoji 来注入，你的正则能拦住吗？**

> 正则层有天然局限（只覆盖已知模式），这正是为什么需要 AI 语义层。AI 不管输入是什么语言/形式，看的是意图。但如果两层都挂了，坦诚承认这是当前方案的局限性，然后讲改进思路（多语言对抗训练、持续补充规则库）。

### 关于 NucleiAI

**Q6：为什么做这个项目？Nuclei 本身不是已经很好用了吗？**

> Nuclei 是规则匹配引擎——告诉你匹配到了，不告诉你是不是误报。安全团队每天花 30% 时间人工审核。我的目标是加一层 AI 分析自动过滤。

**Q7：AI 分析从逐条改成批量，除了速度还有别的收益吗？**

> 有。LLM 看到全部结果的全局上下文时，能做更好的相对判断。比如它能看到"这条 SQL 报错 + 这条堆栈泄露 + 这条是教程页"，三者对比后判断更准。这是意外收获。

**Q8：你说 5 条硬规则修正 AI 误判，能具体讲一条吗？你遇到过 AI 判错、硬规则纠正的案例？**

> 挑 XSS 转义检测讲：body 含 `&lt;script&gt;` 但无真实 `<script>` 标签 → 说明用户输入已被 HTML 实体编码 → 绝对安全。有次 AI 看到响应里有 script 字样就判漏洞，硬规则自动修正为误报。

**Q9：你怎么验证 AI 判得对？**

> 对照实验。每个靶场端点设计时就标注了 ground truth（真漏洞/误报干扰），5 轮重复测试记录波动。8B 模型波动 75%-100%，最终轮 100%。所以不是说"AI 准"，而是说"混合防线保证稳态 90%+"。

**Q10：如果 Ollama 挂了怎么办？**

> 架构支持优雅降级。AI 模块不可用时，filter_results() 返回默认判定（类型 unknown、标记为非误报），扫描正常执行。报告生成也有纯代码 fallback 统计。整个系统不依赖 AI 也能跑。

## B. 技术基础（考察基本功）

**Q11：Python 的 async/await 和同步函数有什么区别？为什么你的 FastAPI 项目要用 async？**

> 同步函数阻塞线程，async 遇到 I/O 等待时释放控制权给事件循环。FastAPI 调用外部工具（Nuclei subprocess、Ollama HTTP API）都是 I/O 密集操作，用 async 可以并发处理多个请求而不阻塞。

**Q12：FastAPI 和 Flask 有什么区别？为什么不选 Flask？**

> FastAPI 原生 async 支持 + 自动 OpenAPI 文档 + Pydantic 数据校验 + 性能接近 Node.js。Flask 是同步框架，需要用扩展库才能实现这些。我的项目需要处理较长时间的扫描任务，async 更合适。

**Q13：你在项目里用 subprocess 调用 Nuclei（Go 写的），Python 怎么处理跨语言数据交换？**

> Nuclei 支持 `-jsonl` 输出，每行一个 JSON 对象。Python 通过 subprocess.run() 执行命令，捕获 stdout，逐行 json.loads() 解析。中间格式是 JSONL，桥接 Go ←→ Python。

**Q14：SQLite 适合生产环境吗？为什么你的项目用它？**

> 适合本地/单机场景和原型验证，不适合高并发写入。我项目定位是本地工具而非 Web 服务，SQLite 零配置、零维护。如果上生产，我会迁移到 PostgreSQL 并增加连接池管理。

**Q15：`split("\r\n\r\n")[0]` 这个 Bug 你是怎么发现的？**

> AI 判定结果一直很差，不符合预期。我开始怀疑 Prompt 问题，调整了几轮没改善。然后回到数据源头——打印了传给 AI 的响应摘要，发现全是 HTTP 头（Content-Type、Server 等），完全没有页面正文。AI 实际上在盲猜。改成 `[0][:200]` 取头 + `[1][:600]` 取体后，准确率立刻提升。

## C. AI 安全专项（面试官可能会试探你的深度）

**Q16：你觉得当前 LLM 最大的安全风险是什么？**

> 两条线。应用层：Prompt Injection（尤其是间接注入——RAG 场景下通过检索到的恶意文档注入），因为这是 LLM 独有的、传统安全体系完全不覆盖的攻击面。系统层：Agent + Tool Use 下的权限失控——LLM 被诱导执行危险操作。OWASP Top 10 for LLM 2025 把这两项排在前两位。

**Q17：间接注入和直接注入有什么区别？为什么更危险？**

> 直接注入是用户直接在对话框输入恶意指令。间接注入是攻击者通过外部数据源（网页、文档、知识库）注入，用户在不知情的情况下触发。RAG 应用检索到含隐藏指令的文档 → LLM 执行指令 → 泄露信息。用户看不到恶意输入，更难防范。

**Q18：你怎么评估一个 LLM 的安全性？有想过系统化的评估框架吗？**

> 我项目里的 Model Arena + 多轮测试就是初步的评估框架——同一攻击载荷，多模型并发，控制变量对比。如果要系统化：按攻击面分类（越狱/PII/工具滥用/有害内容），每个类别设标准测试集，记录通过率和防御退化曲线。这其实也是我项目后续想做的方向。

**Q19：本地部署 8B 小模型做安全分析，最大的限制是什么？怎么解决？**

> 最大限制是输出一致性——8B 量化模型面对同样输入，多次输出结果可能不同，准确率 75%-100% 波动。我的方案是混合防线：AI 做语义判断 + 硬规则做确定性兜底。如果资源允许，升级到 32B 或云端大模型能从根本上减少波动。

**Q20：你有关注过模型的注意力衰减问题吗？多轮对话安全性退化怎么解决？**

> 这正是我 LLM 沙箱项目里讨论过的问题。多轮对话中，System Prompt 的有效注意力随上下文增长而衰减——模型逐渐"忘记"安全约束。我当时的方案是：当前架构采用无状态设计（每次请求隔离），天然免疫多轮攻击。如果必须保持记忆，可以 Anchoring——在每轮拼接历史前，强制重注入最高优先级的安全指令，保证模型生成回复前看到的最后一行永远是安全底线。

## D. 行为/设计题（考察思维过程）

**Q21：如果让你从零设计一个 Web 漏洞扫描器，你会怎么做？**

> 分层：信息收集（httpx 指纹 + 爬虫）→ 漏洞检测（模板引擎，参考 Nuclei 的 YAML 驱动方式）→ 结果分析（AI 误报过滤）→ 报告输出。关键是模块解耦，每层可以独立替换。

**Q22：如果 AI 分析的结果和我们预期不符，你怎么排查？**

> 我的排查逻辑：先确认输入对不对（数据层）→ 再确认 Prompt 合不合理（指令层）→ 最后怀疑模型能力。项目里的修复经历就是按这个顺序——最终定位到数据层 Bug。

**Q23：你项目里最大的技术难点是什么？怎么克服的？**

> 选一个具体的讲。推荐讲响应摘要 Bug 或 Prompt 迭代过程——有故事有方法，比说"技术选型"这种虚的强得多。

**Q24：你的项目如果继续做下去，下一步会做什么？**

> 三个方向：① 接入更大模型验证准确率上限；② 前端重构为 React/Vue（当前是服务端渲染）；③ 支持 Nuclei 官方全量模板库，按指纹智能选择。思路清晰，优先级明确。

**Q25：你对安全行业的哪个方向最感兴趣？为什么？**

> AI 安全，尤其是 LLM 应用安全（Prompt Injection、RAG 安全、Agent 安全）。原因是：这个方向太新，传统安全专家还在学习 LLM、AI 专家不懂安全，交叉领域空间大。我的两个项目刚好在这个交叉点上——一个攻 LLM、一个用 LLM 做防御。
