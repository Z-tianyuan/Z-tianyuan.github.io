### 二、渗透测试完整流程

#### 阶段 1：环境接入

HTB 靶场机器运行在内网，需要先通过 OpenVPN 接入：

```bash
# 1. 从 HTB 官网下载 .ovpn 配置文件
# 2. 安装 OpenVPN Connect 并导入配置
# 3. 连接后获得 VPN IP（本次为 10.10.16.80）

# 验证连通性
ping 10.10.16.1       # VPN 网关，延迟 ~225ms
ping 10.129.0.1       # 机器网络，延迟 ~226ms
```

确保 `10.129.0.0/16` 网段已加入路由表：

```
route print | grep 10.129
  10.129.0.0  255.255.0.0  10.10.16.1  # ← 流量走 VPN
```

---

#### 阶段 2：信息收集（端口扫描）

拿到目标 IP 后，第一件事永远是 **nmap 扫描**，搞清楚目标开放了什么服务：

```bash
nmap -sV -T4 -Pn 10.129.133.100
```

**参数说明：**

| 参数 | 作用 |
|------|------|
| `-sV` | 探测服务版本信息 |
| `-T4` | 扫描速度（T0-T5，T4 适合实战） |
| `-Pn` | 跳过 ping 探测（防火墙可能禁 ping） |

**扫描结果：**

```
PORT   STATE  SERVICE VERSION
23/tcp open   telnet  (Telnet service)
```

**关键发现：** 目标仅开放 23 端口，运行 Telnet 服务。

---

#### 阶段 3：漏洞分析

看到 Telnet（端口 23），立刻想到以下常见弱点：

1. **空密码/弱密码** — 管理员忘记设置密码
2. **默认凭证** — 厂商出厂默认账户未修改
3. **CVE 历史漏洞** — 查询 Telnet 服务版本是否有已知漏洞

作为一个 Tier 0 入门靶机，大概率是第一种——用户配置失误。

---

#### 阶段 4：漏洞利用

使用 Windows 自带的 Telnet 客户端连接：

```bash
telnet 10.129.133.100
```

成功连接后提示登录，尝试常见弱凭证：

```bash
login: root
password: (直接回车，空密码)
```

**结果：** 成功获得 root 权限，无需任何提权。

**为什么能成功？** Telnet 协议本身不加密，且目标系统未为 root 账户设置密码——这是典型的"配置漏洞"而非软件漏洞。

---

#### 阶段 5：Flag 获取

登录成功后，定位并读取 flag 文件：

```bash
ls                # 列出当前目录文件
cat flag.txt      # 读取 flag
```

常见 flag 位置：
- `/root/flag.txt`
- `/home/用户名/flag.txt`
- 当前工作目录

将拿到的哈希值提交到 HTB 平台，完成本机。

### 三、关键技能总结

拿到 IP 后的标准思维链：

```
IP：10.129.133.100
     │
     ▼
┌─────────────────────┐
│  nmap -sV -Pn <IP>  │  ← 第一步永远是扫描
└──────┬──────────────┘
       │
       ▼
┌─────────────────────┐
│  23/tcp → Telnet    │  ← 识别服务类型
└──────┬──────────────┘
       │
       ▼
┌─────────────────────┐
│  弱密码/空密码？     │  ← 针对服务类型思考攻击面
│  CVE？默认凭证？    │
└──────┬──────────────┘
       │
       ▼
┌─────────────────────┐
│  telnet <IP>        │  ← 执行攻击
│  root / (空密码)    │
└──────┬──────────────┘
       │
       ▼
┌─────────────────────┐
│  cat flag.txt       │  ← 获取 Flag
└─────────────────────┘
```

**核心原则：** 不要猜，要扫描。nmap 告诉你目标有什么，你再针对性地打什么。

### 四、修复建议

| 问题 | 建议 |
|------|------|
| Telnet 明文传输 | 替换为 SSH，禁用 Telnet |
| root 空密码 | 设置强密码（12位以上，含特殊字符） |
| root 远程登录 | 禁用 root 远程登录，使用普通用户 + sudo |
| 无访问控制 | 配置防火墙，限制可连接 Telnet 的源 IP |
| 无日志监控 | 启用登录审计日志，接入 SIEM/SOC |

### 五、拓展思考

**1. 如果这台机器 SSH 端口也开放，流程怎么变？**

```
22/tcp → SSH → hydra 爆破 / 已知 CVE → 获得 shell
```

**2. 如果这台机器开了 80 端口？**

```
80/tcp → HTTP → 目录扫描 (gobuster) → 网站指纹 → 针对性 Web 漏洞测试
```
